# NAA.md: дизайн главной и техническая основа

## Цель

Создать продающий сайт NAA.md для автозапчастей в Слободзее. Основной фокус — запчасти Mercedes-Benz; в дальнейшем каталог также поддерживает Lexus, BMW и другие марки, а сайт ведёт к услугам автосервиса, автомойки, русификации и автомобилям в наличии.

Первая реализация должна быть визуально близка к утверждённому референсу: плотный, зрелый каталоговый интерфейс с большим светлым баннером, спокойной типографикой, небольшими радиусами, минимальными тенями и без декоративных секций, не несущих пользовательской пользы.

## Локализация и SEO

- Русский — язык по умолчанию на `/`; румынская версия — на `/ro/`.
- Обе версии получают собственные заголовки, описания, текстовый контент и локализованные URL страниц каталога.
- Добавляются `canonical`, `hreflang` (`ru`, `ro`, `x-default`), sitemap, robots и структурированные данные для организации, товаров, хлебных крошек и статей.
- Адрес отображается как `Слободзея, ул. Новосовицкая 25`. Статус региона не указывается до появления подтверждённых юридических реквизитов.
- Материалы для медиа создаются как черновики. Публикация возможна только после проверки владельцем.

## Первый экран

### Шапка

Главная строка повторяет смысл и плотность референса:

- словесный логотип `NAA.md`;
- широкий поиск по коду, модели и категории;
- иконки «Мой аккаунт», «Избранное», «Корзина»;
- компактный переключатель `RU | RO` рядом с контактами;
- временные контакты: `+373 68 123 456`, `Пн–Сб 09:00–18:00`.

Под ней размещается тонкая вторичная навигация: `Каталог запчастей`, `Автосервис`, `Автомойка`, `Русификация`, `Автомобили в наличии`.

### Основная зона

- Слева: редактируемый список категорий. Категории с референса являются стартовыми данными, а не фиксированной разметкой.
- Справа: слайдер для 4–5 управляемых баннеров. В первой версии отображаются два активных слайда о Mercedes; пустые позиции посетителям не показываются.
- Слайды переключаются каждые три секунды, плавно, с ручными стрелками, поддержкой клавиатуры и паузой при наведении или взаимодействии.
- Первый слайд: «Запчасти для Mercedes-Benz» с кнопкой «Каталог Mercedes», ведущей в общий каталог Mercedes.
- Под баннером: полоса преимуществ, затем адаптивная сетка популярных категорий с изображением, названием, счётчиком и ссылкой.
- Ниже: VIN-форма, создающая заявку менеджеру, и блок помощи.

На мобильном устройстве боковые категории открываются отдельной панелью; поиск, контакты и действия шапки сохраняют доступность без горизонтальной прокрутки.

## Компоненты и данные

Интерфейс строится из повторно используемых компонентов: `Header`, `SecondaryNav`, `SearchField`, `ActionIcon`, `CategorySidebar`, `HeroCarousel`, `BenefitStrip`, `CategoryCard`, `VinRequestForm`, `HelpPanel`, `ProductCard` и базовых форм/кнопок. Компоненты не зависят от конкретной страницы и получают контент через типизированные модели.

Будущая админка управляет:

- марками, моделями, категориями, товарами и их фотографиями;
- порядком и видимостью категорий;
- баннерами, их текстом, ссылкой, порядком и языковыми версиями;
- контентными страницами, статьями, SEO-метаданными и маркетинговыми идентификаторами;
- заявками из корзины, VIN и форм услуг.

Товар поддерживает фиксированную цену в MDL и режим «Уточнить цену». Покупатель может отправить заказ без регистрации. VIN на первом этапе не вызывает внешнюю базу, а отправляет защищённую заявку с VIN и контактами менеджеру.

## Техническая архитектура

- Frontend: Next.js, TypeScript, Tailwind CSS, серверный рендеринг публичных SEO-страниц.
- Backend: отдельный ASP.NET Core API на C# с версионированными контрактами. До подключения полной бизнес-логики frontend использует безопасные mock-адаптеры на тех же моделях.
- Данные: PostgreSQL. В БД хранятся только записи и ссылки на медиа.
- Медиа: S3-совместимое объектное хранилище; через CDN отдаются оптимизированные варианты изображений. Это исключает дорогое хранение фотографий в базе.
- Нагрузочная устойчивость: CDN-кэш, серверный кэш для публичных страниц, пагинация, лимиты размеров файлов, оптимизация изображений, ограничения запросов и мониторинг ошибок.

## Безопасность и админка

- У владельца одна административная учётная запись, не более двух активных сессий на устройствах. Третья попытка входа отклоняется, пока одна из сессий не будет завершена владельцем.
- Сессии хранятся серверно; браузер получает только `HttpOnly`, `Secure`, `SameSite` cookie. Токены не хранятся в `localStorage`.
- Администратор защищён многофакторной аутентификацией, стойким хэшированием пароля через стандартный механизм ASP.NET Core Identity, ограничением попыток входа и аудитом действий.
- API использует авторизацию на каждом защищённом маршруте, CSRF-защиту для cookie-сессий, строгую валидацию входных моделей, параметризованные запросы, allowlist CORS, CSP и безопасные заголовки.
- Загрузка медиа выполняется ограниченными подписанными URL после проверки MIME-типа, размера и прав доступа. Публичные файлы не получают прав на выполнение.
- Публичные формы и вход защищены rate limiting; критичные события логируются без паролей, токенов и персональных данных в открытом виде.

## Проверка качества

- Визуальная проверка desktop и mobile против утверждённого референса.
- Проверка клавиатурной навигации, фокуса, контраста, паузы слайдера и доступных названий иконок.
- Unit-тесты для моделей данных и форм; интеграционные тесты для будущих заявок, сессий и лимита двух устройств.
- Проверка локализованных URL, метаданных, `hreflang`, sitemap и отсутствия дублей страниц.
- Нагрузочные и security-проверки API выполняются до подключения настоящей админки и публикации.

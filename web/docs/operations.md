# CRM и Telegram оператора

Приложение использует PostgreSQL. Перенос из первой версии на SQLite завершён; скрипт переноса и проверки, работавшие с SQLite, удалены в П2 (ищите в истории git, если понадобятся).

## Запуск

Из каталога `web`:

```powershell
npm run db:up
npm run db:migrate
npm run dev
```

`db:import` предназначен для разового переноса старой SQLite. Повторные вставки пропускаются. Старые висячие предложения без товара не переносятся; исходный SQLite остаётся на месте. Скрипты сотрудников `staff:create-owner`, `staff:create` и `staff:list` работают с Postgres.

## CRM

- `/admin/requests`: доска из шести этапов. На компьютере карточки перетаскиваются; на телефоне используется список с переключателем этапа и фильтрами «мои / сегодня / просрочено». Отказ требует выбора одной из пяти причин. Версия обращения защищает от перезаписи чужого изменения.
- Кнопка «Звонок» есть в верхней панели, в меню «+» и в CRM. Введите телефон, имя и что нужно клиенту. Совпадение по международному номеру продолжает карточку клиента. Объединённые телефоны сохраняются как дополнительные номера.
- В обращении: предложение из деталей склада, текст для копирования и передачи через Viber, Telegram или WhatsApp; создание заказа с подставленными контактами; задача с датой и временем; ожидание поступления по названию.
- `/admin/clients`: контакты, машины текстом, теги, тип, заметки, персональная скидка СТО, обращения, заказы и общая лента. Скидку назначает владелец; она рассчитывается сервером в предложениях и новых заказах. Объединение карточек доступно владельцу.
- `/admin/tasks`: сегодня, просроченные, завтра. Сотрудник завершает свои задачи; владелец — любые.
- `/admin/reports`: воронка по источникам, конверсия в выдачу, причины отказов, число повторных покупателей и СТО.

Заказ или заявка с сайта создают клиента и обращение в той же транзакции. Новый заказ привязывается к последнему открытому обращению этого клиента без заказа. Выдача заказа закрывает обращение. Каталог, заказ, движение остатка и журнал используют единые серверные функции.

## Подключение Telegram

Создайте бота через BotFather. Токен хранится только в `.env.local`, который исключён из Git. В окружении приложения нужны:

```dotenv
DATABASE_URL=postgres://...
NEXT_PUBLIC_SITE_URL=https://ваш-домен
TELEGRAM_BOT_TOKEN=токен-из-защищённого-поля
TELEGRAM_BOT_USERNAME=имя_без_собаки
TELEGRAM_TRANSPORT=polling
OPERATIONS_SECRET=случайный-длинный-секрет
TELEGRAM_WEBHOOK_SECRET=другой-случайный-секрет
OPERATIONS_APP_URL=http://localhost:3000
```

Для локальной разработки `NEXT_PUBLIC_SITE_URL` может быть `http://localhost:3000`; ссылки из Telegram на localhost доступны только с самого компьютера. Для оператора на телефоне нужен доступный адрес сайта. Два внутренних секрета уже сгенерированы в локальном окружении; их значения не выводятся в отчёт.

```powershell
node scripts/telegram-setup.mjs
npm run operations:worker
```

Setup проверяет токен через `getMe`, сохраняет имя бота и переключает Telegram в выбранный режим. В режиме polling публичный webhook не нужен. Worker получает обновления, сохраняет их в Postgres, обрабатывает действия и отправляет очередь. Приложение и worker должны работать одновременно. Для постоянной работы worker запускается отдельной службой с автоматическим перезапуском.

В `/admin/profile` нажмите «Подключить Telegram», откройте выданную ссылку и нажмите Start. Ссылка действует 10 минут и используется один раз. Каждый сотрудник подключает собственный Telegram. Бот молчит в группах и для непривязанных людей. Удалённый или выключенный сотрудник теряет доступ. «Отключить» удаляет привязку и неиспользованные приглашения.

В production можно выбрать `TELEGRAM_TRANSPORT=webhook` и снова запустить setup. Webhook проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`. Обработчик только сохраняет обновление; worker продолжает обслуживать очередь и напоминания. Альтернатива постоянно работающему worker — вызов `POST /api/operations/tick` раз в минуту с `Authorization: Bearer <OPERATIONS_SECRET>`.

## Действия и напоминания

- Заказ: позиции, итог, получение, звонок, подтверждение, отсутствие на складе, отмена и ссылка в админку. Telegram разрешает в URL-кнопках HTTP/tg-ссылки, поэтому «Позвонить» открывает защищённую страницу сайта с кнопкой `tel:`. Требуется вход сотрудника.
- Подтверждение использует те же проверки статуса и остатка, что и админка. Далее бот спрашивает получение, при необходимости адрес, стоимость и язык RU/RO. Отмена требует причины. `/cancel` сбрасывает незавершённый диалог.
- Заявка: создание заказа по введённым SKU, отсутствие на складе и открытие CRM.
- `/sold SKU`, `/stock SKU`, `/find текст`, `/today`.
- Напоминания работают с 08:00 до 20:00 по `Europe/Chisinau`. После 30 минут повтор — каждые полчаса; после двух часов отдельное уведомление владельцам. В 19:00 — одна сводка на сотрудника в день. Выручка относится к дате выдачи, новые заказы — к дате создания.
- Задачи напоминаются в рабочие часы. Поступление товара с подходящим названием, категорией и донором создаёт готовый текст для назначенного оператора; если оператор не назначен — для подключённых сотрудников.

Обновления Telegram сохраняются с уникальным `update_id`; повтор доставки одного обновления не повторяет действие. Нажатие старой кнопки подтверждения не списывает остаток повторно. Отправка хранится в `telegram_outbox`, ошибки повторяются с задержкой; для HTTP 429 используется `retry_after`. После закрытия заказа уже отправленные сообщения редактируются, а ещё не отправленные собираются заново без телефона и адреса.

## Проверки

```powershell
npx vitest run
npx tsc --noEmit
npx eslint src
npm run build
node qa/crm-browser-smoke.mjs
npm run qa
```

Интеграционные тесты создают отдельную случайную схему Postgres и удаляют только её. Они проверяют путь «звонок → предложение → заказ → выдача», объединение, поступления, скидку СТО, привязку, повторные нажатия, права, конкуренцию за последнюю деталь и повторы отправки. Браузерная проверка создаёт собственные временные записи и удаляет их по точным идентификаторам.

Без настоящего токена пройдены локальные проверки обработчиков и имитация ответов Telegram. Реальная доставка и работа кнопок в мобильном Telegram требуют токена и привязки сотрудника.
